A cloud for small software.

Your agent hands this server a folder. It hands back a link you can send to someone. Hosting, a database, file storage, sign‑in and sharing are already there.

Get started View on GitHub
terminal
# three lines from a folder to a link you can send
npx smallcloud login https://cloud.example.com
npx smallcloud deploy ./standup
# → https://cloud.example.com/a/standup
npx smallcloud share standup bob@example.com

Bob gets a link, signs in with his email, and uses the tool. Your app sees him as ctx.user.email.

01  /  What an app is

A folder. Nothing to provision.

No Dockerfile, no database to spin up, no auth library, no environment to wire. Three things, and the platform supplies the rest through one ctx object.

standup/
  app.json            {"name": "Standup Notes"}
  public/index.html   the frontend
  api/notes.js        one file per route
// api/notes.js
export default (req, ctx) => ({
  json: ctx.db.all(
    'select * from notes order by id desc'
  )
})
02  /  The ctx object

Everything an app gets.

ctx.db

This app’s own SQLite database — run, get, all, exec.

ctx.files

Per‑app file storage — put, get, list, delete.

ctx.user

The signed‑in person as {email}, or null on a public app.

ctx.env

Secrets the owner set — never checked into your code.

ctx.fetch

Outbound HTTP, with private and internal addresses blocked.

ctx.log

Writes to the app log, readable with smallcloud logs.

03  /  Sharing

Send a link. They sign in with email.

Roles are user (can open it) and editor (can also redeploy and manage sharing).

bob@example.comjust Bob, after he signs in
domain:acme.comanyone with an email at that domain
publicanyone with the link, no sign‑in
04  /  Built for agents

A tool your coding agent can drive.

smallcloud ships an MCP server, so an agent can deploy, share and debug with no human in the loop — smallcloud_deploy, smallcloud_logs, smallcloud_db and the rest.

npx smallcloud mcp-install   # registers with Claude Code

Point it at the app contract — the one document an agent needs — and ask for a tool.

05  /  What it deliberately is not

Honest about its edges.

  • noNot a scale‑out cloud. It is for software that will only ever have a few users.
  • noNot a place to let strangers deploy code. Open it only to people you would hand a shell.
  • noNot a code generator, and not a no‑code builder. It is the deploy‑and‑share layer.
  • noNo lock‑in. smallcloud export hands back your source, database and files.
